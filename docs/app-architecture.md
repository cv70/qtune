# Qtune App 架构

## 1. App 角色

Qtune App 是设备的控制中枢和内容入口，承担三类职责：

- `设备控制`：连接、校准、配置、状态展示
- `创作编辑`：模式管理、模板编辑、录制处理
- `内容入口`：作品浏览、模板获取、发布和账户同步

## 2. 核心模块

### 2.1 设备中心

负责：

- 设备发现和配对
- 设备状态显示
- 校准流程管理
- 固件信息和基础设置

### 2.2 模式中心

负责：

- `光影钢琴`
- `音乐画布`
- `节奏冒险`

用户可以从统一入口切换模式，并查看每种模式的最近使用配置。

### 2.3 音乐画布编辑器

负责：

- 新建和编辑控制界面模板
- 放置打击垫、滑条、旋钮和触发区
- 配置颜色、触发逻辑和参数映射
- 实时预览同步到设备端

### 2.4 录制与编辑

负责：

- 发起演奏录制
- 合并相机画面、界面状态和音频
- 添加滤镜、字幕、封面和导出参数

### 2.5 内容中心

负责：

- 浏览作品、模板和谱面
- 收藏、下载和再次使用模板
- 发起发布和查看互动反馈

### 2.6 账户与同步

负责：

- 登录、资料管理
- 作品同步
- 模板和收藏同步
- 设备绑定关系管理

## 3. 关键数据对象

- `ModeConfig`：模式级参数
- `CanvasElement`：单个控制元件
- `CanvasTemplate`：完整画布模板
- `RecordingSession`：录制过程状态
- `DraftPerformance`：待编辑或待发布作品草稿
- `SyncState`：本地与云端同步状态

## 4. 关键流程

### 4.1 设备配对流程

1. 发现附近设备
2. 选择目标设备并完成绑定
3. 拉取能力信息与固件信息
4. 建立可复用的设备档案

### 4.2 模板编辑流程

1. 用户创建新模板
2. 在编辑器中放置元件
3. 为元件配置音乐行为
4. 保存本地草稿
5. 同步到设备和云端

### 4.3 录制发布流程

1. 选择模式和模板
2. 发起录制
3. 完成演奏并生成草稿
4. 编辑封面、文案和标签
5. 发布到社区或导出到外部平台

## 5. 架构原则

- `实时体验前置`：与设备交互相关的关键配置操作优先轻量、直接
- `编辑与发布解耦`：模板编辑和作品发布是两条相邻但独立的流程
- `离线优先`：本地模板和作品草稿应具备基础离线可用性
- `统一内容模型`：模板、谱面和作品在 App 中保持稳定概念边界

## 6. 主要风险

- 模式入口过多导致首页信息密度失控
- 模板编辑器能力膨胀导致首版学习成本升高
- 录制和上传链路过长，打断即兴创作体验

因此 `V1.0` 需要控制复杂度，优先保证设备连接稳定、模板编辑可用、录制分享可完成。
