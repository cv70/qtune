# Qtune 平台架构

## 1. 平台目标

Qtune 平台负责承接产品中的“内容”和“关系”。它不是单纯的视频社区，而是围绕音乐模板、谱面、演奏作品和创作者运营构建的内容平台。

## 2. 平台核心对象

- `User`：平台用户
- `CreatorProfile`：创作者主页和认证信息
- `CanvasTemplate`：可复用的控制界面模板
- `Chart`：节奏玩法和练习谱面
- `Performance`：用户作品
- `Collection`：收藏夹、专题或活动集合
- `Campaign`：活动挑战和运营主题

## 3. 平台能力分层

### 3.1 内容生产层

负责：

- 模板上传
- 谱面上传
- 作品发布
- 活动投稿

### 3.2 内容管理层

负责：

- 元数据管理
- 标签和分类
- 审核流转
- 违规内容处理

### 3.3 内容分发层

负责：

- 推荐流
- 热门榜单
- 搜索
- 专题页和活动页

### 3.4 社区互动层

负责：

- 点赞、评论、收藏、关注
- 作品二次引用
- 模板复用和挑战参与

### 3.5 运营后台

负责：

- 内容审核
- 推荐规则配置
- 活动管理
- 创作者合作和数据观察

## 4. 核心业务链路

### 4.1 模板分发

1. 创作者上传模板
2. 平台补充元数据并审核
3. 模板进入推荐流或专题集合
4. 用户在 App 中下载并应用到设备

### 4.2 谱面挑战

1. 平台发布官方或创作者谱面
2. 用户在 App 中参与挑战
3. 演奏结果生成作品并回流平台
4. 平台形成榜单和挑战页

### 4.3 作品传播

1. 用户发布作品
2. 平台计算分发策略
3. 用户产生互动和二次创作
4. 创作者积累粉丝、模板使用量和活动参与度

## 5. 架构原则

- `内容对象分层明确`：模板、谱面、作品不能混成一个泛内容模型
- `App 与平台解耦`：App 是入口，但平台能力应独立可运营
- `冷启动友好`：官方内容和精选模板必须能够支撑早期活跃度
- `创作者优先`：平台需要让创作者有持续输出的动力

## 6. V1.0 边界

`V1.0` 平台只需要完成基础闭环：

- 用户可浏览作品、模板和部分谱面
- 用户可发布作品并完成基本互动
- 平台具备基础审核和推荐能力

以下能力放在后续版本逐步扩大：

- 更复杂的创作者收益体系
- 更强的活动运营工具
- 更开放的第三方内容生态
